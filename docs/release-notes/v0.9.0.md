## TL;DR

- **New:** claudes manages sessions across several Claude accounts, including
  claude-swap (cswap) profiles.
- **New:** `--account ACCOUNT` narrows a command to one account.
- **Changed:** Restart, ping, and resume run `claude` with the session's own
  account.
- **Changed:** `claudes doctor` checks cswap files and warns about running
  sessions in a skipped profile.

This release makes claudes aware of more than one Claude Code account. If you
use one account, the output does not change.

## Behavior changes

### Accounts

claudes now treats every Claude Code directory it finds as an account:

- your own directory, `~/.claude`
- the profiles that claude-swap (`cswap run`) runs sessions in
- directories you add to `config.yaml` under `accounts.dirs`

Every command that lists or acts on sessions now covers all accounts. Add
`--account ACCOUNT` to narrow it to one. `ACCOUNT` is a name from `config.yaml`.
As cswap accepts them, it can also be an account number, an alias, or an email.

```sh
claudes ls --account work
```

Each `claude` call runs with the session's own account in `CLAUDE_CONFIG_DIR`. A
restart, ping, or resume keeps its login and daemon. For `~/.claude`, claudes
leaves the variable unset.

### cswap profiles

claudes reads cswap's `sequence.json` and its profiles only when `cswap` is on
your `PATH`. It skips a profile that names no current account.

### `claudes doctor`

`claudes doctor` checks those cswap files against `cswap list --json`. It warns
when sessions are running in a skipped profile. (#17)
