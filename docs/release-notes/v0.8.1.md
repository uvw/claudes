## TL;DR

- **Fixed:** On Windows, `claudes stop` and `--interactive` now ask a session to
  exit before killing it.
- **Fixed:** On Windows, killing `claudes` alone now also ends the
  `claude agents` view it started.

This release fixes two Windows problems. Both make claudes behave on Windows the
way it already does on Unix.

## Behavior changes

### `claudes stop` and `--interactive` (Windows)

Before, an interactive session was killed outright and saved nothing at exit.
Now claudes sends Ctrl-Break first and kills whatever is left after five
seconds. The session saves its last prompt and cost state, and your shell stays
open. In testing, a stop took about 1.4 seconds (#15).

claudes still kills the session straight away in three cases:

- A program other than a known shell shares the session's console.
- `cmd` is running a batch file, such as npm's `claude.cmd`.
- The session is the one claudes itself runs in.

### `claudes` with no command (Windows)

Running `claudes` starts `claude agents` and waits. If you kill `claudes` alone,
for example from Task Manager or `Stop-Process`, `claude agents` now ends with
it. Before, it kept running and kept reading the console. Claude Code's
background service and your background sessions are not affected (#13).

## Platform notes

- Windows: both fixes apply only to Windows. Unix behavior is unchanged.
